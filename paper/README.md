# Manuscript and reproducibility

`main.tex` is the local manuscript source. `references.bib` is its complete
bibliography; the `references-additions.bib` and `references-new.bib` files are
historical leftovers and are not used. Figure 1 is TikZ in `main.tex`. The other
figures are generated by `analysis_la_cetsp/make_figures.py`.

## Rebuild from released results

From the repository root, with Python 3.10 or newer:

```sh
python -m pip install -r paper/requirements-results.txt
python tools/test_diagnostic_metrics.py
python tools/export_paper_results.py
python analysis_la_cetsp/make_figures.py
python tools/texcheck.py
cd paper
latexmk -pdf main.tex
```

Alternatively, use Tectonic 0.17.0:

```sh
tectonic -X compile main.tex --keep-logs --keep-intermediates --outdir ../output/pdf --untrusted
```

Create the output directory first. Tectonic downloads TeX packages on its first
run. The CAS class already loads `stfloats`; do not add `dblfloatfix`.
Upload this folder's `main.tex`, the three CAS support files, `references.bib`,
`generated/*.tex`, `thumbnails/` and the referenced figure PDFs to Overleaf. Generated inputs
are committed so compiling the paper does not require running Python.

The CAS support files and email/URL icons come from Elsevier's
[els-cas-templates 2.4 distribution](https://ctan.org/pkg/els-cas-templates)
(LPPL 1.3c). Their original notices are retained.

## What is reproducible from this release

- `analysis_test/parsed/`: parsed run summaries, training, calibration, rejection
  and convergence records from the end-to-end experiment. The raw console-log
  parser from the earlier analysis is not part of this release.
- `tools/export_paper_results.py`: rebuilds full/active model summaries, paired
  tests, activation counts, source hashes, the instance manifest and generated
  LaTeX inputs. Other existing summary CSVs retain their historical provenance.
- `analysis_la_cetsp/results/`: retained model/feature diagnostic measurements,
  regenerated stage/LKH measurements, and corrected full-VND sensitivity results.
  Plotting uses these CSVs and never silently reselects raw logs.
- `paper/generated/input_hashes.csv`: hashes of the parsed and diagnostic inputs
  used for this version. CSVs are the source for plots and generated tables.

This release reproduces tables and plots from the retained measurements. It does
not claim a bitwise reconstruction of every historical model fit: the original
JSON logs, run selections for older probes and all environment details are not
bundled. Raw solution logs are available from the authors on request. No new
53-instance solver experiment or prospective gate validation was run for this
review.

## Statistical conventions

The end-to-end set has 53 instances, five runs and ten islands (2,650 rows).
Run-level ratios match instance and run IDs to island 9; island seeds are offset
by island ID. The mean of ratios differs from the ratio of mean costs. Rejection
percentage is the mean of `100 * ml_rejects / effective_iter`.

Wilcoxon tests use differences of per-instance mean cost/runtime, rounded to ten
decimal places. They use the normal approximation, `zero_method='wilcox'`, no
continuity correction and a two-sided alternative. Quality includes all 53
instances; speed includes the 47 with at least one rejection. The displayed
effective sample size excludes zero differences. Recalculation corrects the
historical GBSA quality sample count and some p-values; no significance decision
changes. Runtime is to the stopping rule under island contention, not time to a
common target quality. No compute-weighted speedup is inferred.

Model/oracle and lineage fits use GroupKFold by run. Univariate, diversity and
partial-VND scores are direct concordances; the historical multivariate population
probe uses solution-level KFold and is exploratory. Feature-family bars therefore
do not share one evaluation protocol. `best` in oracle/lineage CSVs is the mean
of within-instance model maxima, an optimistic selection convention, not the
maximum of model means. Only oracle and lineage sets have matched clock controls.

## Corrected rank--gain diagnostics

With the appropriate JSON logs under `solutions/ml_logs/`:

```sh
python analysis_la_cetsp/pre_predicts_post.py
python analysis_la_cetsp/lkh_character.py
python analysis_la_cetsp/calibrate_recorded_cohorts.py
python tools/export_paper_results.py
python analysis_la_cetsp/make_figures.py
```

The first two use instrumented island-0 records and all qualifying runs for their
three named instances. Stage correlations average adjacent-stage Spearman values
over runs; end-to-end correlations pool observations. LKH kappa averages per-run
Spearman(post-greedy recorded-cohort percentile, relative LKH gain).

The corrected full-VND script selects 25 named instances, up to three recent
island-9 runs per instance and the last 800 solution files in **numeric** order.
It records selected run IDs, counts and input hashes in `kappa_run_manifest.csv`.
Changing the available logs can change selected runs and results. The current
manifest is the record of the data used for the manuscript.

Full-VND kappa uses pre-VND recorded-cohort percentile and relative full-VND gain.
The 25-instance mean is approximately 0.889; observed direct cost-rank concordance
is approximately 0.560. A Gaussian copula reassigns observed gains, five repeats
per run and eleven nominal settings, using seed 0. Membership stays fixed.
Realised kappa is measured, not assumed equal to its nominal value. Gains of
records with undefined input-cohort percentile stay fixed.

Cost-rank concordance counts agreement over pairs with distinct output
percentiles, credits input ties by one half and excludes output ties. It is not
rescaled Kendall tau-b or a survival concordance. The test includes a case where
high kappa coexists with perfectly preserved order, demonstrating why kappa alone
cannot be an impossibility test.

The historical `kappa_calibration.py` is retained with a warning and a separate
default `legacy_results/` output directory. Its pooled-cost kappa (formerly 0.953)
and rescaled tau-b are superseded; do not use them to regenerate current figures.

## Scope and remaining evidence needs

`analysis_la_cetsp/results/instance_manifest.csv` distinguishes the test and
development sets and each diagnostic subset. The five-instance model/oracle
sample includes one development instance; full-VND sensitivity includes eight.
These retrospective diagnostics are exploratory.

The historical logger omits unadmitted offspring and terminal control survivors.
Diagnostic loaders also exclude zero-lifetime records. Cohorts reconstructed from
these samples omit live members. The reported discrimination and rank diagnostics
are conditional on recorded admitted positive-lifetime solutions, not an unbiased
sample of all generated offspring. The fitted oracle is an empirical reference,
not a universal ceiling. The diversity probe uses directed Chamfer distance
(at most 80 points and 15 cohort peers), not the solver's edit distance.

Closing these evidence gaps requires new complete logging and experiments.
Matched-rate random pruning, within-time evaluation, time-plus-feature controls,
and time-to-target measurements remain prospective work. The manuscript describes
them as limitations, not as completed checks.
